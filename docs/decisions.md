## 1. 日次の売上サマリ → 号機×列ごとの販売本数（2026-08-05）

- **詰まっていたこと**：最初の通知は日次の売上サマリだった。でも運用側が補充を判断するのに要るのは、号機の中の**列ごとの本数**だった
- **判断**：通知を列ごとの表だけにした。日次売上と在庫のまとめ、CSV添付は外した
- **採らなかった案**：商品名でまとめる案。システムに登録されている商品が1台1つだけなので、まとめても号機の合計と同じになる
- あわせて、1日2回だった通知を、夜間の集計の確定時刻に合わせて毎晩1回にした

## 2. 通知ツール → 月次請求のパイプライン（2026-10-01）

- **詰まっていたこと**：月次締めで、画面から売上を写してExcelに貼り、取引先ごとのシートで計算していた。旧Excelには `#REF!`・行ズレ・単価の直書きが埋もれていた
- **判断**：取得クライアントに月次の売上明細を出すサブコマンドを足した。売上はシステムの実績だけを正にし、契約条件はマスタに出し、請求書は**検証を通ったときだけ**ドラフトで出す形にした
- 発行は自動にせず、人が承認してから出す（自動化するのは作業で、承認ではない）

## 3. 運用の初月で直したこと（2026-10-02〜10-09）

実際に流したことで、設計の段階では見えなかった問題が出た。

| 出てきた問題 | 判断 |
|---|---|
| 同じ月の draft を流し直すと、発行台帳にドラフト行が重なる | 同じ月のドラフト行は置き換える。承認済みの行は残す |
| 卸の売上が、手数料の計算と売上の集計の両方に入ってしまう | 対象IDの付いた行は請求の経路だけに入れ、集計は対象IDが空の行だけにする |
| ブックがスプレッドシートで保存されて、PDFの先頭にREADMEが出た。整数が小数になる、ロックが外れる、なども起きた | PDF化のときに開くシートを明示した。崩れたブックを元の形に戻すスクリプトを作った。のちに「正本をスプレッドシートで開いて保存するのは禁止」になった |
| 発行日を「翌月1日」に固定していたが、運用側の方針は「作成当日」だった | 発行日をPDFを作った日に変えた |
| 「一定額未満は固定額」の契約がほかにもあった | 最低保証の列で吸収した（式は増やさない） |
| サーバが応答せず、取得が約40分止まった | 1回の試行に15分の上限を設けた。失敗したら20分後に1回やり直し、それでもだめなら0以外で終わって、タスク側の再実行に任せる |

## 4. 人が入れる売上の取り込み方（2026-11-06 → 11-09 で再転換）

- **最初の判断（11-06）**：EC・催事・卸の売上は、入力用のスプレッドシートに人が入れる。それを閲覧専用のサービスアカウントで読み、正本の対象月の行だけを置き換える。書く前に写しを残し、行が無ければ止まる
- **詰まったこと**：入力用スプシと正本の2か所に同じ数字がある状態になった。正本側で数字を直しても、取り込みを流し直すと入力用スプシの古い値で上書きされて戻る
- **再転換（11-09）**：移行先では入力用スプシをやめ、正本のシートに直接入れる。上書きの原因になる取り込みジョブは、移行先からは外した

## 5. Excel 正本 → スプレッドシート正本（2026-11-06〜11-08、進行中）

- **詰まっていたこと**：Excel正本はDrive上にあり、スプレッドシートで開かれると壊れる。計算・PDF化が1台のPCとLibreOfficeに依存していた
- **ゴール**：2026-12分から Excel を使わない。スプレッドシートを正本にし、計算・請求書PDF・発行台帳は Python のジョブが作る

途中の判断:

| 判断 | 理由 |
|---|---|
| xlsx を丸ごと取り込まず、スプレッドシートは最小構成をゼロから作る | 丸ごと取り込むと、型・保護・数式が壊れた前例がある |
| 手での取り込みをやめ、API で書いて読む | 年月やIDが数値に化けない。全セルを読み戻して照合できる |
| 請求額の計算を1つの Python モジュールにまとめ、スプレッドシートには結果を値で書く | Excel の数式と Python の検算とスプレッドシートの数式の3重実装を避ける |
| 契約の行に適用期間を持たせる | 料率を変えたときに過去月の金額が動かないようにする |
| 台帳とPDFの突き合わせを、検証の計画から外す | どちらも Excel からの出力なので、一致しても証拠にならない |
| 承認済みの台帳行と金額が食い違ったら、ジョブを止める | 発行済みの請求書と後から食い違うのを防ぐ |
| ジョブが書く範囲はロックし、入れてよいセルだけ色で示す | 人の入力とジョブの書き込みがぶつからないようにする |
| 本番のスプレッドシートは、試作を昇格させず、切替の日に作り直す | 試作には検証の跡（書き換えて戻した行、保護の試行）が残っている |
| 集計・グラフのシートは後回し | あとから作れる。先に、誰が何のために見ているかを確かめる |

ここまでの状態：本番用スプレッドシートに過去15か月分を入れたリハーサルで、直近月の請求額と請求書の中身が10社とも Excel と一致した。2026-11分を両方で回して照合してから、切り替えるかどうかを決める。

## 6. PDF作成を手元のPCから外す試み（2026-11-08、試作）

- **詰まっていたこと**：請求書PDFの作成が作業者のPCでしか動かない。出し直しのたびに作業者が手を動かす必要がある
- **やってみたこと**：クラウドの Windows 実行環境で請求書を描けるかを試し、標準で入っているフォントに切り替えた。シートのチェックボックスで出し直しを依頼すると、ジョブがPDFを作ってDriveに置く仕組みを試作した。外部サービスの鍵は作業者だけが持つスクリプトに置き、シートの編集者からは読めないようにした
- **状態**：試作の段階。本番では動かしていない
